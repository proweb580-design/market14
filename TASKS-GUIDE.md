# TASKS-GUIDE — Простое руководство для новичка

Этот файл подробно объясняет, как устроен новый порядок разработки: **сначала мы создаём красивый, полностью готовый интерфейс сайта со всеми страницами на моковых данных**, чтобы сразу видеть результат своими глазами, а уже затем подключаем базу данных, Telegram Mini App и в последнюю очередь мобильное приложение на Expo.

---

## Как работать с Cursor
1. Откройте папку проекта в Cursor.
2. Откройте `TASKS.md` и найдите первую задачу без `[x]`.
3. Отправьте Cursor только эту задачу, а не весь список.
4. Попросите объяснить, какие файлы он создал/изменил и как проверить результат в браузере.
5. Запустите проект (`npm run dev`) и проверьте результат.
6. Если всё работает, отметьте задачу `[x]` и сохраните изменения в Git.

# ЧАСТЬ 1. САЙТ, ДИЗАЙН И ВСЕ СТРАНИЦЫ (МОКОВЫЕ ДАННЫЕ)
*Вы сразу получаете работающий сайт, где можно кликать по каталогу, открывать товары, добавлять их в корзину и оформлять заказ, не тратя время на настройку базы данных.*

### Этап 0. Подготовить инструменты
Установка Node.js, инициализация TypeScript и репозитория Git. База данных на этом этапе ещё не нужна.

**Запрос для Cursor:**
> Выполни T-001–T-004 из TASKS.md. Создай структуру папок, package.json с TypeScript, команды запуска dev и build, а также .gitignore и .env.example.

**Проверка:** `node -v` и `npm -v` выводят версии, в терминале работает `npm run build`.

---

### Этап 1. Сделать каркас и моковые данные (Mock Data)
Моковые данные (`mockProducts.ts`) — это массив готовых товаров, категорий и брендов прямо в коде. Они позволяют сразу наполнить сайт реалистичными карточками цифровой техники с ценами в сумах (UZS) и характеристиками.

**Запрос для Cursor:**
> Выполни T-010–T-013. Настрой Express с EJS-шаблонами (layouts и partials). Создай файл с качественными моковыми товарами для магазина техники в Ташкенте (смартфоны, ноутбуки, бытовая техника с ценами в UZS, фото, описанием). Сделай так, чтобы главная страница открывалась по адресу http://localhost:3000.

**Проверка:** запустите `npm run dev`. В браузере открывается каркас сайта с шапкой и подвалом.

---

### Этап 2. Создать дизайн-систему и главную страницу
Создаём премиальную тёмную тему: глубокий тёмный фон (`#0B0D12`), контрастные поверхности карточек, акцентные фиолетовые и бирюзовые кнопки, Bento-сетку баннеров и категорий на главной.

**Запрос для Cursor:**
> Выполни T-020–T-024. Настрой CSS-токены дизайн-системы, адаптивную шапку с поиском и счётчиками, карточку товара и Bento-сетку главной страницы с демонстрационными товарами. Проверь отображение на мобильных 360px и ПК.

**Проверка:** главная страница выглядит современно и дорого, карточки товаров отображаются красиво, меню открывается на смартфонах.

---

### Этап 3. Каталог и страница товара (на моках)
Каталог позволяет фильтровать моковые товары по категориям, брендам и ценам, искать по названию и сортировать. Динамический маршрут `/product/:slug` показывает детальную карточку конкретного товара.

**Запрос для Cursor:**
> Выполни T-030–T-034. Создай страницу /catalog с фильтрами, сортировкой и поиском по моковым товарам. Создай страницу товара /product/:slug с фотогалереей, характеристиками и кнопками добавления. Добавь страницу 404.

**Проверка:** при клике на любой товар открывается его персональная страница с подробностями; фильтры в каталоге мгновенно отбирают нужные товары.

---

### Этап 4. Корзина, сравнение и избранное (LocalStorage)
Чтобы корзина, избранное и сравнение работали сразу без базы данных, мы сохраняем их в браузере через `localStorage`. Пользователь может перезагружать страницу — товары не пропадут.

**Запрос для Cursor:**
> Выполни T-040–T-044. Реализуй добавление товаров в корзину, избранное и сравнение через LocalStorage. Сверстай отдельную страницу /cart с пересчётом сумм в UZS, страницу /favorites и страницу /compare с таблицей характеристик. Добавь аккуратные пустые состояния.

**Проверка:** добавьте товар в корзину — в шапке обновляется счётчик; на странице `/cart` можно менять количество и видеть пересчёт суммы; избранное и сравнение сохраняются после обновления страницы.

---

### Этап 5. Оформление заказа, аккаунты и проверка пути пользователя
Создаём финальные страницы сайта: форму оформления заказа с адресом по Ташкенту, страницу успешного заказа, интерфейс входа/регистрации и личный кабинет.

**Запрос для Cursor:**
> Выполни T-050–T-054. Сделай страницу оформления заказа /checkout, экран успеха /checkout/success, формы /login и /register, а также личный кабинет /account с историей демо-заказов.

**Проверка:** пройдите путь покупателя от каталога до кнопки «Оформить заказ» и перехода на страницу успеха. Весь сайт готов к визуальной демонстрации!

# ЧАСТЬ 2. БАЗА ДАННЫХ И СЕРВЕРНАЯ БИЗНЕС-ЛОГИКА
*Теперь, когда весь интерфейс готов и утверждён, мы подключаем постоянное хранилище и переносим данные из моков в реальную базу.*

### Этап 6. База данных Neon и Prisma ORM
Neon — серверная PostgreSQL база в облаке. Prisma — инструмент для работы с базой из TypeScript. Моковые товары переносятся в `seed.ts` и загружаются в Neon.

**Запрос для Cursor:**
> Выполни T-060–T-065. Подключи Neon через Prisma, опиши схему данных из SPEC.md, примени миграцию и заполни базу товарами через seed-скрипт. Переведи страницы каталога и товара на чтение из Neon вместо мокового файла.

**Проверка:** товары загружаются из настоящей базы данных Neon.

---

### Этап 7. Аккаунты, серверная корзина и заказы в БД
Реальные пароли хешируются через `bcrypt`, сервер хранит сессии, а заказы сохраняются в таблице `Order` с проверкой остатков.

**Запрос для Cursor:**
> Выполни T-070–T-074. Настрой серверную авторизацию (сессии, bcrypt, Google OAuth), привязку корзины к пользователю и транзакционное создание заказов в Neon. Защити чужие заказы от просмотра.

**Проверка:** регистрация и вход создают реального пользователя в БД, оформленный заказ отображается в личном кабинете.

---

### Этап 8. Тестовая оплата Stripe и публикация
Подключение платежей, автоматические тесты и публикация сайта на хостинге.

**Запрос для Cursor:**
> Выполни T-080–T-083. Подключи тестовый Stripe Checkout с подписанным webhook, напиши тесты корзины и заказа, подготовь инструкцию по развёртыванию в README.

**Проверка:** тестовый платёж переводит заказ в статус `paid`; тесты проходят без ошибок.

# ЧАСТЬ 3. TELEGRAM MINI APP (TMA)
*Интеграция магазина в Telegram — самый востребованный формат для покупателей в Ташкенте.*

### Этап 9. Telegram Mini App
Сайт открывается прямо внутри Telegram. Пользователю не нужно вводить логин и пароль — вход происходит по `initData` от Telegram. Нативные кнопки Telegram (`MainButton`) управляют корзиной и оформлением.

**Запрос для Cursor:**
> Выполни T-090–T-094. Подключи Telegram WebApp SDK, настрой валидацию initData на сервере для входа в один клик. Адаптируй интерфейс под тему Telegram и Safe Area. Настрой отправку подтверждения заказа через Telegram-бота.

**Проверка:** откройте ссылку на сайт через тестового Telegram-бота: магазин открывается прямо в приложении Telegram, подстраивается под тему мессенджера, а после заказа бот присылает чек.

# ЧАСТЬ 4. МОБИЛЬНОЕ ПРИЛОЖЕНИЕ (EXPO / REACT NATIVE)
*Создание отдельного мобильного приложения для Android и iOS.*

### Этап 10. Мобильное приложение на Expo
Приложение пишется на React Native + Expo. Для проверки используются **два режима в Expo Go**:
1. **Режим LAN:** `npx expo start --lan` — разработка на телефоне в домашней/офисной Wi-Fi сети.
2. **Режим Tunnel:** `npx expo start --tunnel` — тестирование приложения через интернет на любом смартфоне без общего Wi-Fi.

Для финальной сборки автономного APK-файла (без Expo Go) настраивается облачная сборка **Expo EAS Build** (`eas.json`).

**Запрос для Cursor:**
> Выполни T-100–T-105. Создай проект React Native в папке mobile/ с Expo SDK. Стандартизируй JSON API бэкенда. Настрой запуск через Expo Go в режимах LAN и Tunnel. Реализуй мобильные экраны и настрой eas.json для сборки релизного APK.

**Проверка:** приложение открывается в Expo Go по QR-коду в обоих режимах; автономный APK собирается через EAS Build и устанавливается на Android-смартфон.

## Мини-словарь
- **Моковые данные (Mock Data):** демонстрационные данные прямо в коде, позволяющие верстать и тестировать весь интерфейс без подключения внешней базы.
- **LocalStorage:** встроенное хранилище браузера для временного сохранения корзины и избранного.
- **Neon PostgreSQL:** облачная реляционная база данных для долговременного хранения данных.
- **Prisma:** удобная библиотека (ORM) для работы с базой данных из TypeScript.
- **Telegram Mini App (TMA):** веб-приложение, работающее внутри Telegram с доступом к нативным кнопкам и аккаунту мессенджера.
- **Expo:** платформа для быстрой разработки приложений на React Native под Android и iOS.
- **Expo Go:** мобильное приложение для мгновенного предпросмотра кода без сборки установочного файла.
- **EAS Build:** инструмент сборки готовых автономных установочных пакетов (APK, AAB, IPA).
