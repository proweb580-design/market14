# PRD — Интернет-магазин техники для Ташкента

**Версия:** 1.0 · **Статус:** черновик для разработки · **Валюта:** UZS (сум)

## 1. Описание
Интернет-магазин цифровой и бытовой техники для покупателей в Ташкенте. Пользователь изучает каталог, сортирует и фильтрует товары, открывает отдельную страницу товара, сравнивает модели, добавляет их в избранное и корзину, регистрируется или входит через Google и проходит тестовый сценарий оплаты через Stripe Checkout. Каталог, аккаунты и заказы хранятся в Neon PostgreSQL.

Визуальное направление: тёмная тема, bento-grid, крупные фотографии товаров, выразительная типографика, тонкие границы и умеренные эффекты. MediaPark, MCBRO и IDEA — ориентиры по привычным сценариям магазина, но не шаблоны для копирования.

## 2. Цели
- Быстро находить и выбирать технику.
- Понятно сравнивать характеристики.
- Упростить путь от выбора товара до оформления заказа.
- Сохранять корзину и избранное.
- Подготовить безопасную основу для тестирования заказа и платежа.
- Обеспечить удобную работу на телефонах и компьютерах.

## 3. Пользователи и сценарии
- Покупатель ищет товар, выбирает категорию, сортирует список и открывает карточку товара.
- Покупатель сравнивает несколько моделей по характеристикам.
- Покупатель сохраняет товары в избранное и возвращается к ним позже.
- Покупатель меняет количество товаров в корзине, видит суммы и оформляет заказ.
- Пользователь создаёт аккаунт по email/паролю или входит через Google.
- Пользователь проходит тестовую оплату и смотрит историю заказов.

## 4. Обязательный MVP
- Главная с категориями, подборками и популярными товарами.
- Каталог с поиском, фильтрами и сортировкой.
- Динамическая страница каждого товара.
- Сравнение товаров с таблицей характеристик.
- Избранное.
- Отдельная страница корзины: добавить, удалить, изменить количество, сумма каждой позиции и итог.
- Регистрация и вход по email/паролю.
- Google OAuth.
- Личный кабинет и список заказов.
- Оформление заказа с контактами.
- Только тестовый режим Stripe (ключи `sk_test_...`), реальные списания не выполняются.
- Neon PostgreSQL, адаптивный интерфейс, состояния загрузки/ошибок/пустого результата.

## 5. Функциональные требования

### Каталог
- Поиск по названию и бренду.
- Фильтры по категории, бренду, цене и наличию; дополнительные фильтры — по типу товара.
- Сортировка: рекомендуемые, сначала дешевле, сначала дороже, новинки.
- Параметры поиска и сортировки по возможности отражаются в URL.
- Нельзя оформить заказ на количество больше доступного остатка.

### Страница товара
- URL вида `/product/iphone-17-pro` на основе уникального slug.
- Название, бренд, изображения, цена в UZS, наличие, описание и характеристики.
- Действия: «В корзину», «В избранное», «Сравнить».
- Неизвестный slug возвращает 404.
- Цена и наличие повторно проверяются сервером.

### Сравнение
- Добавление из каталога и страницы товара.
- Таблица, в которой товары находятся в колонках, а характеристики — в строках.
- Выделение различий и удаление товара.
- Лимит по умолчанию — 4 товара.
- Для несопоставимых категорий показывать только общие характеристики или предупреждение.

### Избранное
- Гость может хранить список в браузере.
- После входа избранное синхронизируется с аккаунтом.
- Можно удалить товар или перенести его в корзину.

### Корзина и заказ
- Отдельный URL `/cart`.
- Количество от 1 до доступного остатка; удаление позиции.
- Показывать цену за единицу, количество, сумму позиции, промежуточную сумму, доставку (если включена) и итог.
- Гостевая корзина переживает обновление страницы; после входа объединяется с серверной корзиной.
- При оформлении сервер заново проверяет цены и остатки, сам рассчитывает итог и создаёт заказ.
- В истории заказа сохраняются название и цена на момент покупки.

### Аккаунты
- Регистрация, вход, выход, восстановление пароля — предусмотреть до публичного запуска.
- Пароли хранить только в виде безопасного хеша, не в открытом виде.
- Google OAuth настраивается через серверный callback.
- Секреты не попадают в браузерный код или Git.
- Пользователь видит только собственные заказы.

### Тестовая оплата
- Заказ создаётся со статусом `pending_payment`.
- Тестовая оплата не должна выдаваться за настоящее списание.
- Подтверждение проверяется сервером: подписанный webhook Stripe или запрос Checkout Session через Stripe API.
- Повторные уведомления не должны повторно обрабатывать платёж.
- Статусы: `pending_payment`, `paid`, `payment_failed`, `cancelled`, `refunded`.
- Не хранить данные банковских карт.
- До запуска реальных платежей проверить доступность Stripe для продавца (Узбекистан не входит в список стран Stripe — нужно юрлицо в поддерживаемой стране) или выбрать локального провайдера (Payme, Click).

## 6. Дизайн
Стиль: премиальный магазин техники, тёмная тема, bento-сетка, крупные изображения, ясная типографика, спокойные границы. Не перегружать интерфейс свечением, стеклом, градиентами и анимацией. Анимации короткие и полезные; учитывать `prefers-reduced-motion`.

Стартовая палитра:
- Фон `#0B0D12`
- Поверхность `#131720`
- Поверхность выше уровнем `#1A2030`
- Основной текст `#F5F7FB`
- Вторичный текст `#9AA4B2`
- Акцент `#7C6CFF`
- Второй акцент `#22C7D6`
- Успех `#35C98A`
- Ошибка `#FF647C`
- Граница `rgba(255,255,255,0.09)`

Taste skill использовать как проверку композиции, типографики, плотности, отступов, состояний компонентов, адаптивности и отсутствия шаблонного AI-вида. Если он недоступен, применять эти принципы вручную.

## 8. Критерии успеха
- Поиск, сортировка и фильтры дают корректные результаты.
- Страница каждого товара показывает правильные данные из БД.
- Сравнение, избранное и корзина сохраняются и работают после обновления.
- Сумма в заказе пересчитана сервером и совпадает с позициями.
- Пользователь не может читать чужие заказы.
- Статус `paid` выставляется только после серверного подтверждения.
- На ширине 360 px нет горизонтального переполнения.
- В репозитории нет секретов.

## 9. Допущения
- Первая версия на русском языке, валюта — UZS.
- Начальный каталог может содержать демонстрационные товары.
- География доставки в MVP — Ташкент; стоимость доставки нужно определить отдельно.
- Google OAuth требует создать приложение и настроить redirect URL.
- Stripe тестовый сценарий: оплата в USD по фиксированному курсу `STRIPE_UZS_RATE`, сумма заказа хранится в UZS.
